# Đa ngôn ngữ giao diện (i18n)

Giao diện có hai ngôn ngữ: **tiếng Việt** (gốc) và **tiếng Anh**. Chỉ dịch **chữ hệ thống**: nút, menu,
nhãn, tiêu đề, placeholder, toast, trạng thái trống, aria-label, tiêu đề tab. **Không** dịch nội dung do
giáo viên/học viên tạo (bài tập, ngữ pháp, từ vựng), dữ liệu (mã CEFR, tên kỹ năng lưu trong DB) hay
thông báo lỗi server gửi về.

Ngôn ngữ mặc định đặt ở Cài đặt → Thương hiệu (`brand_language`); mỗi người đổi riêng ở menu tài khoản
(lưu `localStorage.ui_lang`, đổi xong tải lại trang).

## Cấu trúc

```
apps/web/src/i18n/
  index.ts        t(), getLang(), setLang()
  registry.ts     SINH TỰ ĐỘNG — node scripts/i18n-registry.mjs
  vi/<ns>.ts      chữ gốc tiếng Việt (nguồn sự thật)
  en/<ns>.ts      bản tiếng Anh, BẮT BUỘC đủ đúng các key của vi/<ns>.ts
```

Mỗi màn hình/nhóm màn hình có **một namespace** riêng (`teacherGrammar`, `userVocab`…). `common` và
`nav` là chung, chỉ người điều phối thêm key vào đó.

```ts
// vi/teacherGrammar.ts
export default {
  "hero.title": "Ngữ pháp",
  "hero.count": "{n} điểm ngữ pháp",
} as const;

// en/teacherGrammar.ts
import type vi from "../vi/teacherGrammar";
const en: Record<keyof typeof vi, string> = {
  "hero.title": "Grammar",
  "hero.count": "{n} grammar point|{n} grammar points",
};
export default en;
```

## Quy tắc khi chuyển một file

1. `import { t } from "<đường dẫn tương đối>/i18n";` rồi thay MỌI chuỗi tiếng Việt hiển thị cho người
   dùng bằng `t("ns.key")`. Key dạng `nhóm.tên` viết camelCase, đặt theo **ý nghĩa** (`toast.saved`,
   `empty.noPoints`, `form.titleLabel`), không theo vị trí (`text1`).
2. Giá trị tiếng Việt = **đúng nguyên văn** chuỗi đang có. Không sửa câu chữ, không đổi dấu câu.
3. Tiếng Anh: tự nhiên, ngắn gọn, giọng giao diện phần mềm (không viết hoa từng chữ, trừ tiêu đề lớn).
   **Ngoại lệ:** chuỗi là *nội dung mẫu bằng tiếng Việt* — placeholder của ô nhập nghĩa/dịch tiếng Việt,
   ví dụ định dạng "English — Tiếng Việt" — thì bản `en` **giữ nguyên tiếng Việt** (người dùng vẫn phải gõ
   tiếng Việt vào ô đó). Tương tự, placeholder là câu tiếng Anh mẫu thì giữ nguyên ở cả hai bản.
4. Biến trong câu: `t("ns.key", { name })` với `{name}` trong chuỗi. Số nhiều tiếng Anh: `"một|nhiều"` +
   tham số `n` (`"{n} word|{n} words"`); tiếng Việt không cần `|`. Dấu `|` chia **cả chuỗi** làm hai bản
   hoàn chỉnh: mỗi bên phải là nguyên câu (sai: `"point|points · a handbook…"`; đúng:
   `"point · a handbook…|points · a handbook…"`).
5. Chuỗi bọc trong `tt(...)` (đổi cô/thầy, tên giáo viên): bỏ `tt`, chỉ cần `t()` — `t()` tự áp `tt` cho
   tiếng Việt. Xoá import `tt` nếu không còn dùng.
6. **Không gọi `t()` ở cấp module** (hằng số ngoài component chạy trước khi biết ngôn ngữ). Hằng số chứa
   nhãn → lưu key kiểu `TKey` (`import { t, type TKey } from ".../i18n"`) rồi gọi `t(key)` lúc render.
7. Câu ghép từ nhiều mảnh JSX (chữ + `<strong>{x}</strong>` + chữ): tách thành vài key ngắn theo thứ tự
   tự nhiên của **cả hai** ngôn ngữ, hoặc dùng tham số. Không ghép chuỗi có ngữ pháp phụ thuộc thứ tự.
8. Dùng key `common.*` khi nghĩa khớp hoàn toàn (Lưu, Huỷ, Xoá, Đang tải…). Không thêm key vào `common`.
9. Không đổi logic, không đổi tên biến, không định dạng lại code ngoài các dòng có chữ.
10. Comment vẫn viết tiếng Anh (RULE #0); không thêm comment mới.

## Khi làm chức năng mới (bắt buộc)

Giao diện **luôn có hai ngôn ngữ**. Mọi chữ mới trong `apps/web/src` đi thẳng vào catalog ngay khi viết,
không viết tiếng Việt cứng rồi "dịch sau".

1. Màn hình đã có namespace → thêm key vào namespace đó. Màn hình mới → tạo cặp `vi/<ns>.ts` +
   `en/<ns>.ts`, chạy `node scripts/i18n-registry.mjs`.
2. Thêm key vào **cả hai** file cùng lúc. Bản `en` có kiểu `Record<keyof typeof vi, string>` nên thiếu
   key tiếng Anh là lỗi kiểu, build không qua.
3. Ưu tiên thêm key mới thay vì đổi tên key cũ: giáo viên có thể đã sửa chữ ở `/teacher/texts`, đổi tên
   key là mất bản sửa của họ. Sửa câu chữ của key cũ thì bản sửa của giáo viên được đánh dấu "cần xem lại".
4. Chuỗi tiếng Việt **cố ý không dịch** (prompt gửi AI, giá trị dữ liệu lưu DB, nội dung mẫu tiếng Việt)
   phải gắn dấu:
   - `// i18n-ignore: <lý do>` trên dòng đó hoặc dòng ngay trên;
   - `// i18n-ignore-start: <lý do>` … `// i18n-ignore-end` cho một khối;
   - `// i18n-ignore-file: <lý do>` cho cả file (file chỉ chứa prompt/dữ liệu).
5. Thông báo lỗi từ API (`HTTPException`) hiện vẫn là tiếng Việt, chưa dịch.

Hook `PostToolUse` (`.claude/hooks/check-ui-i18n.mjs`) chặn mọi Write/Edit trong `apps/web/src` (ngoài
`i18n/`) có chuỗi hoặc chữ JSX tiếng Việt mới mà không có dấu `i18n-ignore`. Codex/agy đọc cùng quy tắc
qua `AGENTS.md` / `GEMINI.md` (symlink tới `CLAUDE.md`).

## Kiểm tra trước khi xong

```bash
cd apps/web && npx tsc --noEmit -p tsconfig.app.json   # thiếu key / sai key là lỗi kiểu
node scripts/check-i18n.mjs --verbose                    # toàn bộ apps/web/src, deploy cũng chạy
# không còn chữ tiếng Việt trong file (trừ comment):
grep -nP "[àáảãạăâđêôơưấầẩẫậắằẳẵặếềểễệốồổỗộớờởỡợứừửữựíìỉĩịúùủũụýỳỷỹỵ]" <file> | grep -vP "^\d+:\s*(//|\*|/\*)"
```

Thêm namespace mới: tạo cặp `vi/<ns>.ts` + `en/<ns>.ts` rồi chạy `node scripts/i18n-registry.mjs`.
